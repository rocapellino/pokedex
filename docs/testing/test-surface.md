## 1. Alcance del Inventario

Este catálogo inventaría los archivos de la superficie de pruebas en `rocapellino/pokedex`: qué verifica cada uno, contra qué artefactos, con qué runner y por qué canal de CI/CD se ejecuta.

Solo contiene datos estables: cambia al **añadir, mover o borrar** un archivo, o al editar su descripción en `scripts/test-surface/metadata*.ts`. Editar el contenido de un test existente no lo modifica. Los conteos de casos, líneas y tamaño no se versionan; se consultan con `npm run test:surface`.

## 2. Matriz Canónica de Suites de Testing

| Suite | Nombre | Runner | Comando Principal | Propósito |
| :--- | :--- | :--- | :--- | :--- |
| **`unit`** | Pruebas Unitarias de Aplicación | `node:test (tsx)` | `npm run test:unit` | Pruebas de alta velocidad y aislamiento sobre servicios de dominio, autenticación, caché y repositorios. |
| **`integration`** | Pruebas de Integración de API y Servicios | `node:test (tsx)` | `npm run test:integration` | Pruebas de persistencia PostgreSQL/Drizzle, concurrencia transaccional, rate limits y endpoint de versión. |
| **`security`** | Seguridad, Hardening y DevSecOps | `node:test (tsx)` | `npm run test:security` | Evaluación de políticas de admisión, Network Policies Cilium L7, cifrado DR, secretos Vault y contratos IaC. |
| **`contracts`** | Contratos de Repositorio | `node:test (tsx)` | `npm run test:contracts` | Contratos sobre ADR, gobernanza documental, entrega de imágenes y dependencias, y observabilidad; verifican archivos del repositorio, no la seguridad de la aplicación. |
| **`gitops`** | Contratos de GitOps y Despliegue | `node:test (tsx)` | `npm run test:gitops` | Inmutabilidad de imágenes por digest SHA-256 en ArgoCD y paridad estricta entre entornos dev/preprod/prod. |
| **`frontend`** | Componentes y Controladores Frontend | `node:test + JSDOM` | `npm test` | Pruebas sobre controladores DOM de backoffice, toasts interactivos y componentes modales accesibles. |
| **`e2e`** | Pruebas End-to-End y Accesibilidad | `playwright` | `npm run test:e2e` | Simulación completa de flujos de usuario en Chromium y auditorías de accesibilidad WCAG 2.1 AA con Axe-core. |
| **`performance`** | Rendimiento y Carga (k6) | `k6` | `k6 run tests/performance/k6_stress_test.js` | Pruebas de estrés y límites de latencia HTTP bajo concurrencia continua respetando presupuestos de rate limit. |
| **`ci`** | Paridad y Gobernanza de CI/CD | `node:test (tsx)` | `npm test` | Verificación estructural de consistencia, timeouts y parámetros de ejecución en pipelines de GitHub Actions. |
| **`fuzz`** | API Fuzzing y Pruebas Adversariales | `node:test (tsx)` | `npm run test:fuzz` | Generación caótica y mutacional de payloads HTTP, validación de boundaries y resiliencia ante inputs malformados. |
| **`governance`** | Gobernanza y Contratos de Plataforma (Root) | `node:test (tsx)` | `npm test` | Contratos de tipos, gobernanza documental, reglas de protección de rama, pentesting e impacto de CI. |

## 5. Gobernanza y Detección de Drift

Este inventario no es estático ni manual. Se rige por el protocolo de gobernanza automatizado de `repo-testing`:

1. **Código como Fuente de Verdad:** Si se agrega, renombra o elimina un archivo de test, el inventario debe reconciliarse mediante `npm run test:surface:update`.
2. **Quality Gate en CI:** El comando `npm run test:surface:check` valida que `test-surface.json` y `test-surface.md` coincidan exactamente con lo que se generaría hoy a partir de los archivos en disco y de `scripts/test-surface/metadata*.ts`.
3. **Taxonomía de Cambios:**
   - `NEW_TEST_FILE`: Archivo de test no registrado.
   - `REMOVED_TEST_FILE`: Archivo eliminado del repositorio que aún figura en el catálogo.
   - `CHANGED`: Metadatos publicados de un archivo (tipo, dominio, descripción, artefactos, comandos o CI) distintos de los del catálogo.
   - `STALE_DOCUMENT`: `test-surface.json` o `test-surface.md` no coinciden con lo que se generaría hoy.
   - `BROKEN_TARGET`: Artefacto bajo prueba inexistente.
   - `ORPHAN`: Test en disco no cubierto por ningún script ni workflow.

```bash
# Comandos de gestión de la superficie
npm run test:surface         # Inspeccionar superficie, métricas y drift
npm run test:surface:check   # Validar paridad estricta (CI)
npm run test:surface:update  # Reconciliar catálogo automáticamente
```
